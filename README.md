# git-tree-viz — Git 提交树可视化

把任何本地 Git 仓库的 commit 历史渲染成一张可交互的分支图：多分支并行、合并点、标签一屏可见。纯本地运行，零第三方依赖。

A local Git history explorer with a bilingual Chinese/English UI, interactive branch graphs, commit diffs, sorting, filters, version exports, and local tag management. Python standard library and system Git only; no build step.

需要 Python 3.10+、较新版本的 Git，以及现代浏览器。MIT 开源。

## 功能

### 2026-11-03 界面与详情升级

- 主分支（优先 `main`、`master`，否则当前分支）的第一父历史固定在主泳道。主线位于可用区域宽度约 40% 处，为右侧提交描述留出更多空间；选中提交后树随可用空间左移，右侧展开详情；关闭或按 Esc 恢复。
- 提交行直接显示标题、作者、日期、短哈希及引用。选中节点及直接关联线高亮，保留纵向浏览位置。
- Conventional Commit 类型前缀和彩色徽标：`feat` 绿色、`fix` 珊瑚红、`refactor` 紫色、`perf` 橙色、`docs` 蓝色、`test` 青色、`chore/build/ci` 灰色；支持作用域和 `!`，正文中的 `BREAKING CHANGE:` 也会显示破坏性变更标记。详情同步展示类型，节点和连线保留分支色。
- 搜索框左侧的类型标签支持多选，命中任一已选类型的提交高亮，其余提交和无关连线暗显；`! BREAKING` 单独匹配破坏性变更。再次点击取消选择，点击“全部”清空筛选。保留全部节点、滚动位置和提交关系，搜索及详情仍可使用。
- 排序下拉框提供时间、编辑量、文件数的正序和逆序，共六种。时间按提交显示的作者时间比较；编辑量为新增行数 + 删除行数，合并提交相对第一父提交，根提交相对空树。二进制变更计入文件数、不计文本行数，重命名按删除与新增统计。首次按编辑量/文件数排序会批量读取统计并在当前仓库会话复用；重新打开仓库会刷新。排序保留选中的提交与类型筛选，同值按原始历史顺序稳定排列。非时间排序采用对齐的提交列表并隐藏连线；切回时间排序恢复分支泳道与父子连线。
- 详情提供提交正文、作者邮箱、带时区的时间、完整哈希复制，以及父/子提交跳转。
- 文件变更支持增删统计、二进制文件提示、单文件代码差异，合并提交可切换比较父提交。重命名按删除和新增显示。
- 搜索标题、正文、作者、邮箱、哈希和引用；Enter/向下按钮跳转下一个结果，`/` 聚焦搜索，上下键选择提交，定位 HEAD 快速返回。
- 图谱仅渲染可见区域附近的提交行，仍保留全量关系布局。窄屏详情以覆盖面板打开，支持减少动画的系统偏好。

升级后需要**重启 Python 服务**，只刷新网页不会加载新增的后端接口。若看到“当前运行的是旧版后端”，请结束原有服务后重启，或使用另一端口：

```powershell
python server.py --repo C:\Projects\your-repo --port 8770
```

打开 http://127.0.0.1:8770 。差异接口为 `GET /api/commit?repo=...&hash=...&parent=0&path=...`，`parent` 从 0 开始。差异文本最多显示 200,000 字符，超出时提示截断，可选择单个文件进一步查看。图谱和导出只读源仓库；开启读写后，标签功能会修改源仓库的本地 Git 引用。

验证命令：`python -m unittest test_server.py -q`、`node test_frontend.cjs`。

- **多 lane 分支图**：按 `--date-order` 从新到旧排列提交，自动为并行分支分配泳道，跨 lane 的父子关系用曲线连接
- **引用标注**：分支（蓝）、标签（黄）、远程分支（灰）直接标在对应提交右侧
- **合并与根提交**：合并点画空心大圆 + 虚线（区分第一父/第二父），根提交画方块
- **交互**：鼠标悬停显示该行高亮 + 提交详情 tooltip，单击打开右侧详情面板（完整信息、父/子提交数）
- **零依赖**：后端只用 Python 标准库 + 系统 `git`，前端原生 HTML/CSS/JS，无构建步骤

## 快速开始

### 中英文界面

右上角的语言选项可在 **中文 / English** 之间切换，默认中文，选择会保存在当前浏览器。工具栏、排序、详情、导出、标签、提示和读写警告均支持两种语言，提交正文、作者、路径、分支名和代码差异保持原文。

切换语言会保留筛选、排序、选中提交、滚动位置、导出路径及 Git 选项、待输入的标签名和当前读写权限。导出或标签写入期间暂时禁用语言切换，避免打断正在进行的操作。翻译集中在 `web/i18n.js`，可用 `node test_i18n.cjs` 验证。

### 读写模式与本地标签

右上角默认显示 **“源仓库只读”**。点击后会出现警告弹窗，明确确认 **“启用读写”** 后，才能在提交详情输入标签名并创建本地轻量标签。点击右上角可立即切回只读；刷新页面、重新打开或切换仓库都会恢复只读。后端使用按仓库授权的会话令牌检查标签修改，导出功能不需要开启源仓库读写。

工具栏的 **“撤回软件标签”** 一键撤回当前仓库中本软件创建的全部标签，包含之前会话创建的标签。归属通过 `refs/git-tree-viz/tags/*` 记录并与标签一起原子创建；图谱不展示这些内部引用。撤回时保留手动创建的标签，跳过后来被其他操作修改的标签并提示；不会覆盖同名标签。标签操作只修改本地引用，不改变工作区、HEAD 或当前分支；标签须手动推送到远端。

### 导出选中版本

点击提交，在右侧展开 **“导出此版本”**，填写目标文件夹的绝对路径，然后选择：

- **纯文件快照（默认）**：读取提交对象中的完整文件内容，不带 `.git`，不受 `export-ignore` 影响，也不包含未提交和未跟踪的文件。
- **保留 `.git`**：建立独立的本地仓库并检出该提交，不通过硬链接或 alternates 依赖源仓库。新分支名称可选，留空时为 detached HEAD。

目标须在源仓库之外，不存在或为空，且上级目录已存在。程序先写入同级临时目录，成功后再移入目标，不覆盖已有内容。完成后显示路径、哈希，并可点击“打开文件夹”。源仓库的工作区、分支和 HEAD 均不改变。

导出前会检查特殊内容：子模块只创建空目录，不拉取内容；Git LFS 保留已提交的指针，不下载大文件。纯文件模式的内部符号链接在 Windows 无权限创建时写成链接目标文本，指向导出目录外的链接会拒绝导出。带 Git 模式采用系统 Git 的检出行为。Git 仓库导出会复制历史，所需时间和磁盘空间可能明显大于纯文件快照。

导出与打开目录接口为本机同源的 JSON POST；升级后须重启后端。`/api/export-info` 提供预检查，`/api/export` 执行导出，`/api/open-folder` 只允许打开本次服务成功导出的目录。

### 启动服务

```bash
cd git-tree-viz
python server.py --repo /path/to/any/git/repo
# 打开 http://127.0.0.1:8765
```

Windows 示例：

```powershell
cd C:\Projects\git-tree-viz
python server.py --repo C:\Projects\your-repo
```

默认仓库可通过 `--repo` 指定，也可以用页面顶栏的输入框在运行时切换。

常用参数：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--repo` | 当前目录 | 要读取的 Git 仓库路径 |
| `--port` | `8765` | 本地 HTTP 端口 |

## 技术要点

**数据层**（`server.py`）：通过 subprocess 调用 `git log --exclude=refs/codex/* --all` 导出全部提交（字段用 `\x1f` 分隔、记录用 `\x1e` 分隔，避免与提交信息冲突），再用 `git for-each-ref` 解析分支/标签。附带的 `refs/codex/*` 是自动化工具产生的临时引用，默认过滤掉，不算进业务分支。

**布局层**（`web/app.js`）：两遍扫描。

1. 第一遍（新→旧）：维护 `expected[]` 数组，记录每条泳道正在等待的下一个提交 hash。遇到提交时找到等待它的泳道（没有就挑空闲泳道），再把它第一个父提交登记到当前泳道；额外父提交（合并）各开新泳道。
2. 第二遍：按父提交实际所在泳道画边——同泳道直线，跨泳道三次贝塞尔曲线；合并的第二父用虚线。

这个算法不依赖任何图形库，复杂度 O(n·lanes)，1774 个提交实测渲染无压力。

## 限制与可扩展方向

- 仅读取本地仓库（不直连 GitHub）；如需演示 GitHub 仓库，可 clone 后指向本地路径
- 后端仍一次读取全部提交和关系；前端仅渲染可见提交行，超大仓库（10 万+ 提交）仍可进一步增加数据分页
- 不支持工作区的未提交改动展示（working tree）
